# 吃乎工作台数据与权限约定（P00）

一个社团有用户、项目；项目有多次 Visit。活动的排期、确认、菜品、图片、订单、费用分别归属同一 Visit；项目级总稿和导出可汇总选定的 Visit。两个相同店名的 Visit 不互相合并。

用户使用稳定 UUID；ProjectMember 决定项目组长或组员权限。组长可以管理本项目活动、名单、任务、审稿与费用；组员可管理自己的投票、确认、投稿和私有付款证明，并可编辑项目公共刊发稿及评论。站点管理员与项目组长分开。任何跨项目引用在服务端拒绝。

投票、确认、认领三个概念分开。确认关联最终时间版本；改时间会使旧确认失效。认领含文案与照片两种，分别有唯一主负责人；退出成员的任务转为待转交。任务完成依据实际提交及审稿状态，不依据已读提醒。

菜单候选与实际点单不同。套餐父项计费，子菜可分别评价。订单应付、实际付款、退款、拟报销额不同；PaymentAllocation 将实际付款分配给订单，EvidenceLink 只提供证明，不产生支出。金额使用 Decimal，数据库精度为 12 位、2 位小数。原始图片与派生缩略图分开保存。

每份刊发稿有当前 revision；保存须携带 base_revision 并原子比较。Revision 是不可变历史。冲突以 409 返回最新版本和本次草稿，不静默覆盖。回退创建新 Revision。评论与建议可引用版本，旧建议不直接覆盖新稿。定稿只有组长可重新打开。

站内通知按任务、接收人、类型和截止版本去重。通知服务异常不能影响主要业务。外部身份通过 provider 与 subject 唯一映射，不能按昵称自动合并账号。未来统一平台通过 /api/v1 与服务层接入，不访问内部数据库。

首版假定一个社团；保留 Organization 外键以便后续扩展。账号由管理员批量导入，关闭自行注册；登录成员可从项目大厅或可选邀请链接加入，直到组长结束并归档。加入不会回退已完成节点或自动补记历史参加记录。活动通常 4–10 人；不将人数设成硬上限。保存所有时间为带时区值，界面按 Asia/Shanghai 显示。

API 错误格式：`{"code":"machine_readable_code","message":"简短说明","details":{}}`。标准状态：400 校验失败、401 未登录、403 无权限、404 不暴露资源、409 版本/并发冲突。接口版本 `/api/v1/`。列表分页，默认每页 20、最大 100。

所有费用与原图下载均通过权限校验，不能由公开静态目录直接提供。授权策略在 service/query 层实现，Django 模板和 DRF 复用。服务端不信任客户端传入的 project_id 与子对象关系。

样例测试约定见 `sample-analysis.md`。暂不将目录中的真实姓名、交易号、图片写入测试固件或代码；测试用脱敏数据复现业务数值关系。
