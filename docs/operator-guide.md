# Eatful 使用与维护手册

## 组长路径

1. 使用管理员发放的账号登录，首次登录到 i自强 修改初始密码，再创建测评项目。一个主题可以建立多次到店活动；活动各自保存时间、名单、菜品和费用。
2. 新项目会出现在所有已登录成员的项目大厅，成员可自行加入；项目结束前任何阶段均可加入。邀请链接作为可选入口，成员登录后也能使用，不能绕过项目结束限制。
3. 新建活动，按日期一次生成午餐/晚餐候选时段。投票的“能参加”与正式名单不同；选定时段后，请所有人再次确认“参加/不参加/候补”。改期后旧确认会显示为待重确认。
   当前节点完成或到截止时间后会自动推进；组长也可提前确定时段或完成名单确认。没有候选时段时，不会凭空推进投票。
4. 上传菜单截图，若已配置图像服务，后台自动识别；到“图片识别与校对”检查菜名、价格、套餐父项和可选组，再勾选实际点的菜品并建卡。未配置服务时直接手工建卡。费用项可取消文案和照片任务。
5. 在活动页为文案、照片任务分别认领或转交，设置截止时间。组员在“我的原始测评”保存文案并提交任务；全组可以共同编辑“刊发文案”、评论和提出修改建议。审核后通过，定稿后锁定；恢复旧版本会新建一个版本，不删除历史。
6. 选择需要收入内容包的照片，在项目页根据菜品文案生成总稿；人工改过的总稿不会被自动覆盖。下载内容包后用秀米/小红书继续排版，应用不自动发布。
7. 在费用台账逐笔记录订单、数量、价格语义、优惠、付款、退款和订单分配。订单截图与付款截图分开上传并明确关联。到报销材料页筛选活动，查看差异；缺件可先导出草稿，正式包需补齐或逐项写核对说明。ZIP 内有六列表格、原始证明和索引。旧包保持不变，来源变动会标记过期。
8. 项目页可复制催交摘要发到微信群。站内提醒由调度器按任务截止扫描，重复扫描不会重复推送；已读不代表任务完成。

## 组员路径

登录管理员开通的账号，在项目大厅自行加入；也可用邀请链接。进行中的活动先投票再确认参加，已完成节点不会因新人加入退回。确认后认领菜品文案或照片；文案任务要先填写“我的原始测评”才可提交，照片任务要先上传并关联菜品照片才可提交。共同刊发文案支持保存、评论、建议和冲突比较；断网草稿暂存在当前浏览器本地，恢复网络后需要检查并保存。组员只能看自己的付款/票据原件，组长可以查看项目全部财务凭证。

## 账号与识别配置

管理员批量导入 CSV、成员修改资料和密码、AI 协议/地址/模型及手工模式的详细步骤见 [部署交接](handoff.md)。归档代表项目结束，不再允许新成员加入；既有成员仍可查看。

## 日常维护

- 管理员在 `/admin/` 创建或重置账号、查看后台任务。项目组长权限不等于 Django 管理员权限。
- `python manage.py scan_reminders` 可手动扫描提醒；`python manage.py run_worker --once` 可处理一项识别任务。生产 Compose 中各有独立服务。
- `python manage.py advance_workflows` 可单独推进已完成或过期的投票、确认节点；常规 `scan_reminders` 已包含这一步。若服务长时间停机，恢复后执行一次即可追上截止时间。
- 识别服务故障时，后台任务会有限重试并显示失败原因；失败后可在识别页手动重试。手工录入和导出不依赖识别服务。
- `/api/v1/openapi.json` 提供未来统一平台的接口合同。外部身份通过稳定 UUID 与 `ExternalIdentity(provider, subject)` 映射；不要按昵称合并账号，也不要让未来平台直接写数据库。
- 数据与原图都在私有存储中，Django 鉴权下载。不要让反向代理公开 `/private-media/` 或直接暴露数据库端口。
